LLM_CHAT_CONSOLE の各画面が、何を表示し、どこにデータを持ち、サーバーとどうやり取りするか。

**この文書の位置づけ**: 2026-10-12 時点のコードから書き起こした下書き。
判断がつかなかった所には **【要確認 Q番号】** を付けている（番号は、サーバー側のリポジトリの仕様書からの通し）。

関連する文書は、サーバー側のリポジトリ（`z:\LocalFlaskServer\docs\`）にある。

| 文書 | 中身 |
|---|---|
| `spec/api.md` | 各APIの項目と返却 |
| `spec/data.md` | 設定YAMLの形、ファイルの置き場所 |
| `spec/chat-flow.md` | 世界の選択から発言までの流れ |
| `status.md` | 作りかけ、未実装、見た目だけで処理がつながっていないもの |

## 画面の構成

<div align="right"><a href="#top">▲ 目次へ</a></div>

入口は `index_3column_session.html`（メイン画面）の1つだけ。他の4つは、メイン画面の上に重ねて開く子画面。

| ファイル | 画面 | 開き方 |
|---|---|---|
| `index_3column_session.html` | メイン（チャット） | ブラウザで直接開く |
| `world.html` | 世界カード（世界設定の編集） | 上部メニューの「世界」 |
| `person_card.html?kind=character` | キャラクターカード | 上部メニューの「キャラ」 |
| `person_card.html?kind=player` | プレイヤー設定 | 上部メニューの「プレイヤー設定」 |
| `settings.html` | 接続環境設定 | 上部メニューの「接続環境設定」 |

- 子画面は、メイン画面の中に `iframe` で埋め込んであり、重ねて表示・非表示を切り替える。
- 各子画面の「別窓」ボタンで、同じ画面を別のウィンドウでも開ける。子画面は単独で開いても動く。
- 子画面を開くたびに、キャラクターカードと世界カードは読み込み直す（他の画面での変更を反映するため）。

<a id="s1-1"></a>

### JSの読み込み

<div align="right"><a href="#top">▲ 目次へ</a></div>

どの画面も、次の順で `<script>` を読み込む。モジュールは使わず、すべてグローバル。

1. `js/constant.js` … 定数（APIのパス、保存キーの名前、吹き出しのひな形）
2. `js/common.js` … 共通の関数（サーバーの呼び出し、通知、入力チェック）
3. 画面ごとのJS（`index_3column_session.js` など）

共通で使う定数や関数は、1と2に置く。順番を変えると動かない。

## データの持ち方

<div align="right"><a href="#top">▲ 目次へ</a></div>

データの置き場所は3つある。

| 置き場所 | 中身 | 性質 |
|---|---|---|
| ブラウザ（`localStorage`） | 接続先、選択中の世界とセッション、各一覧の写し | そのブラウザだけのもの |
| LLM_CHAT_CONSOLE のフォルダ | 世界・キャラクター・プレイヤーの設定YAMLと画像 | サーバー経由で読み書きする |
| サーバー | セッション、履歴、記憶 | サーバー経由で読む |

画面はフォルダを直接は読み書きできないので、設定の保存・読み込みもサーバーに頼む。
そのとき、このフォルダの場所（`base_chat_path`）を毎回一緒に送る。

<a id="s2-1"></a>

### ブラウザに保存するもの

<div align="right"><a href="#top">▲ 目次へ</a></div>

メイン画面と子画面は別々のページなので、やり取りは `localStorage` を通して行う。キーの名前は `js/constant.js` の `STORAGE_KEYS` に持つ。

| キー | 中身 | 書く画面 |
|---|---|---|
| `flask_base_url` | サーバーの接続先 | 接続環境設定 |
| `base_chat_path` | このフォルダの場所（**サーバーから見たパス**） | 接続環境設定 |
| `base_path` | LocalFlaskServer の場所（同上） | 接続環境設定 |
| `world_list` | 世界の一覧の写し。`[{id, name}]` | 世界カード、メイン（世界選択） |
| `char_list` | キャラクターの一覧の写し。`[{id, name, tags}]` | キャラクターカード、世界カード |
| `player_list` | プレイヤーの一覧の写し。`[{id, name, tags}]` | プレイヤー設定、世界カード |
| `selected_world_id`、`selected_world_name` | メイン画面で遊ぶ世界 | メイン |
| `edit_world_id` | 世界カードで編集中の世界（遊ぶ世界とは別に持つ） | 世界カード |
| `selected_session_id` | 選択中のセッション | メイン |
| `selected_session_name` | 選択中のセッションの表示名 | メイン |
| `session_list` | 選択中の世界のセッション一覧（サーバーから取った写し） | メイン |
| `button_labels` | ボタンの上の説明文字を出すか（`off` なら消す。無ければ出す） | メイン |
| `model_name` | 最後に確かめた、読み込み中のモデルの名前（接続確認・モデルロードで取る） | メイン、接続環境設定 |

- キーは、すべて `js/constant.js` の `STORAGE_KEYS` に定義し、コードに文字列で直接書かない。
- 一覧（`world_list`、`char_list`、`player_list`）は、フォルダの中身の写し。画面を開いたとき（メイン画面は「世界選択」を
  開いたとき）に `/settings/list_settings` で取り直して書き換える。取れなかったときは、残っている写しを使う。
  世界カードは、登場人物の参照IDの確認に使うので、キャラクターとプレイヤーの一覧も取り直す。
- キャラクター・プレイヤーの一覧の `tags`（付けたタグ）も、設定YAMLの「タグ」から、サーバーが一覧と一緒に返す。

<a id="s2-2"></a>

### 画面どうしの連絡

<div align="right"><a href="#top">▲ 目次へ</a></div>

- 接続環境設定で「適用」を押すと、メイン画面に `settings_applied` という知らせを送る。メイン画面は、設定ウィンドウの題名を2秒間「設定　適用しました。」に変える。
- 世界カードで保存・削除すると、メイン画面に知らせを送る（`js/common.js` の `notifyMainPage`。iframe なら親の画面へ、「別窓」なら開いた元の画面へ）。
  - `world_saved`（`world_id`、`world_name`）: 遊んでいる世界なら、メイン画面の世界名の表示を直す。
  - 接続環境設定で「モデルロード」に成功すると、`model_loaded`（`model_name`）を送り、メイン画面の「使用モデル」を新しい名前にする。
  - `world_deleted`（`world_id`）: 遊んでいる世界なら、メイン画面の世界とセッションの選択を外し、チャット欄と一覧を空にして、選び直すよう通知を出す（セッションはサーバーに残る）。
- キャラクターカードとプレイヤー設定の保存は、知らせない（メイン画面に、それを使った表示が無いため。チャットはセッションに写した画像を使う）。
- それ以外は、`localStorage` に書いて、相手の画面が次に読むのを待つ形。一覧は、開くたびに読み直す。

<a id="s3"></a>

## サーバーの呼び出し

<div align="right"><a href="#top">▲ 目次へ</a></div>

- 接続先は `getFlaskBaseUrl()` で決まる。設定画面の入力欄、`localStorage` の `flask_base_url`、既定値（`http://127.0.0.1:5000`）の順に見る。
- 呼び出しは `js/common.js` の関数を通す。各画面で `fetch` を直接書かない。

  | 関数 | 用途 |
  |---|---|
  | `postJson(path, payload, fallbackMessage)` | JSONを送る（ほとんどの呼び出し） |
  | `requestJson(path, options, fallbackMessage)` | GET、または画像（`FormData`）を送る |

- どちらも、HTTPエラーか、返事の `ok` が `true` でないときに例外を投げる。
  例外の `message` にはサーバーの `message` が入るので、そのまま通知に出せる。サーバーが `message` を返さなかったときは `fallbackMessage` が入る。
- 通知は `showToast(文, 種類)` で画面右上に出す。

### 配置

<div align="right"><a href="#top">▲ 目次へ</a></div>

```
┌ 上部メニュー（畳める。「ロック」で開いたままにする）──────────────┐
│ 各子画面を開くボタン ／ 選択中世界・サーバーの接続状態・使用モデル  │
├──────────────┬──────────────┬─────────────┤
│ チャットログ      │ 発言キャラクター  │ 設定              │
│                  │ 立ち絵          │  セッション選択    │
│ キャラパラメータ枠 │                │  世界設定           │
│ チャット入力枠    │                │ 返信生成結果画像    │
│ [新規チャット][発言]│          │                  │
└──────────────┴──────────────┴─────────────┘
```

- 右の「世界設定」は「世界選択」のボタンだけ。生成の設定（温度、最大トークン数）は画面に出さず、サーバーの `files/settings/generation.yaml` で変える。
- 「返信生成結果画像」の欄は、画像生成の連携（サーバー側の Q37）を作るまで、置き場所として残す（今は何も出ない）。
- 上部の「ラベル ON/OFF」は、ボタンの上の説明文字（上部メニューの各項目名と、右の「世界選択」の見出し）を出す・消す切り替え。
  選んだ状態はブラウザ（`button_labels`）に覚えておき、開き直しても続く。
- 上部の「タグ」で、タグ管理のウィンドウが開く（下の「タグ」）。

<a id="s4-2"></a>

### 開いたとき

<div align="right"><a href="#top">▲ 目次へ</a></div>

1. `localStorage` から選択中の世界を読み、上部に表示する。
2. 世界が選ばれていれば、`/load_session_list` でセッション一覧を取り、表示する。前回開いていたセッションがあれば開き直す（下）。
3. サーバーの接続確認（`/health`）は、開いたときと、上部の「確認」を押したときに行う。結果は3通りに出し分ける。

   | 表示 | 意味 |
   |---|---|
   | ●接続中（緑） | 正常 |
   | ▲異常（黄） | サーバーは起動しているが、異常がある。理由は通知に出し、文字にマウスを載せても見える |
   | ×未接続（赤） | 応答が無い（サーバーが止まっている、接続先が違う） |

4. 上部の「使用モデル」には、接続確認で返ってきた、モデルサーバーが読み込み中のモデルの名前を出し、ブラウザ（`model_name`）に覚えておく。
   - 開いた直後や、サーバーに接続できないときは、前に覚えた名前を出す（一度も確かめていなければ「未確認」）。
   - モデルサーバーが止まっているときは「（モデルサーバー未接続）」、モデルを読み込めていないときは「（モデルが読み込まれていません）」を名前のうしろに付ける。
   - 接続環境設定で「モデルロード」に成功したら、メイン画面に `model_loaded` を知らせ、「使用モデル」を新しい名前にする。

- 開き直したとき、前回開いていたセッション（`selected_session_id`）が、遊ぶ世界のセッション一覧にあれば、その履歴を読み込んで開いた状態にする。
  一覧に無い（消された、別の世界のもの）・一覧が取れないときは、選択を外す（選択だけ残ると、チャット欄が空のまま発言したときに、そのセッションへ送られてしまうため）。

### 操作と呼ぶAPI

<div align="right"><a href="#top">▲ 目次へ</a></div>

流れの詳細は、サーバー側の `spec/chat-flow.md`。

| 操作 | 画面がやること |
|---|---|
| 「世界選択」→ 世界を選ぶ | `/world_start`。選択中の世界を保存し、セッション一覧を出す |
| 「新規チャット」 | `/chat_startup` → `/new_chat`。チャット欄を空にして、開始メッセージを出す |
| 「発言」／入力欄で Enter | 自分の吹き出しを足してから `/chat`。返事と、あれば掛け合い（キャラクター同士の1往復）を、返ってきた順に吹き出しで足す。失敗したら、自分の吹き出しを消して文章を入力欄に戻す（もう一度押せば送り直せる。「再送」ボタンは無い） |
| セッション一覧の行を押す | `/selected_session`。チャット欄を履歴で置き換える |
| 畳まれた履歴の印を押す | `/selected_message`。印をその10件で置き換える |
| セッションにチェック →「選択削除」 | `/delete_session` |
| 吹き出し・アイコンを押す | その発言者の立ち絵を中央に出す |
| 「持ち物」 | `/session_items`。立ち絵の上に持ち物のウィンドウを重ねて開く（下の「持ち物」）。もう一度押すか「×」で閉じる |

- 世界が選ばれていないと「新規チャット」はできず、セッションが選ばれていないと「発言」はできない（通知を出して止める）。
- サーバーを待っている間は、押したボタンを押せなくする。
- **初期記憶の作成中**: 新規チャットのあとと、セッションを開いたときに `/session_status` を1秒ごとに問い合わせる。
  作成中の間は「発言」（と Enter での送信）を押せなくし、入力欄の上にプログレスバーと今の段階
  （例: `初期記憶を作成中: 白井　結: 分類 （3/8）`）を出す。
  - できたら、バーを消して「初期記憶ができました」と通知する。
  - 失敗したら、ボタンは戻し、バーの代わりに「初期記憶の作成に失敗しました（世界の記憶／キャラクターの記憶）。
    新規チャットを押し直してください。」を赤字で出す。失敗の内容は、文字にマウスを載せると見える。
  - 「新規チャット」は作成中でも押せる。別のセッションを開いたら、前のセッションの問い合わせはやめる。
- **発言のあとの記憶の更新中**: 返事を出したあと、サーバーは裏でキャラクターの記憶を更新する（`complete_stage` = `after`）。
  初期記憶と同じく問い合わせ、終わるまで「発言」を止めてバーを出す（例: `記憶を更新中: 白井　結: 記憶の更新 （0/1）`）。
  - 終わったら、バーを消す（発言のたびに出るので、通知は出さない）。
  - 失敗したら、ボタンは戻し、「記憶の更新に失敗しました（キャラクターの記憶）。記憶は前のままです。」を赤字で出す。

- **持ち物**: 「持ち物」を押すと、真ん中の立ち絵のパネルの上に、持ち物のウィンドウを重ねて開く。
  - 上の段に、セッションのメインキャラクター全員（`参照種別` が `character`）を並べる。サブ・モブ・プレイヤーは出さない（持ち物を持たない扱い）。
    開いたときは先頭の人を選んだ状態にし、押した人の持ち物を下の段に出す。
  - 下の段は、「○○ の持ち物」の見出し、所持品の一覧（1つずつリンク）、所持金（例: `所持金: 10,000円`。無ければ「なし」）。
  - 所持品のリンクを押すと、その持ち物の名前を見出しにした中身のページを出す。今は白紙（契約書・履歴書などの中身は、あとで入れる）。
    「← 持ち物の一覧へ」で戻る。
  - 持ち物はキャラクターの記憶から読み、発言のあとに変わるので、開くたびに取り直す。セッションが選ばれていなければ、通知を出して開かない。
  - 新規チャット・セッションの切り替え・世界の選び直しをしたときは閉じる。

### 入力欄のキー操作

<div align="right"><a href="#top">▲ 目次へ</a></div>

| キー | 動き |
|---|---|
| Enter | 発言する |
| Shift + Enter、Ctrl + Enter | 改行する |
| PageUp／PageDown | チャットログを1画面ぶん上下に動かす |
| Home／End | チャットログの先頭／末尾へ |
| Ctrl + P | （ ）を入れる（下）。入力欄にいるときは、ブラウザの印刷の代わりにこれをする |

- **（ ）行動**: 「発言」の隣のボタンと Ctrl + P で、入力欄に「（）」を入れる。セリフではない行動・思考・時間の経過を書くときに使う
  （例: `（問診票を書き終えるまで待っている）`）。サーバーは、発言の（ ）の中を、セリフではなく行動・時間の経過として読む。
  文字を選んでいればその文字を囲み、選んでいなければカーソルの位置に入れて、かっこの中にカーソルを置く。

<a id="s4-5"></a>

### 吹き出し

<div align="right"><a href="#top">▲ 目次へ</a></div>

- ひな形は `js/constant.js` の `BASE_CHAT_OBJECT`（キャラクター・システム用）と `BASE_CHAT_OBJECT_USER`（プレイヤー用）。
- 誰の発言かは、サーバーが返す履歴の `role` で分ける（古い履歴は `role` が無く、`character_id` が `player`）。

  | 見分け | 扱い |
  |---|---|
  | `role` が `player`（古い履歴は `character_id` が `player`） | プレイヤーの吹き出し |
  | `character_id` が `system` | 畳まれた履歴の印 |
  | それ以外 | キャラクターの吹き出し |

- 発言した直後の自分の吹き出しは、サーバーが `/new_chat`・`/selected_session` で返す `player`（このセッションのプレイヤー）で出す。
  返事が来たら、`/chat` が返す `player_line_id` を行番号として入れる。

- アイコンと立ち絵は、セッションに退避した画像（`/session_image/...`）から読む。`characters/` のフォルダを直接は読まない。
  プレイヤーも同じで、セッションに退避したプレイヤーのアイコンを出す。無いときは、名前の頭文字を出す。

<a id="s5"></a>

## 世界カード（`world.html`）

<div align="right"><a href="#top">▲ 目次へ</a></div>

- 左に世界の一覧、右に編集欄。
- 画面の高さが足りないときは、入力欄（過去・現在・未来・目的・補足、シナリオの目標・パラメータ・開始メッセージ）を潰さずに、最低4〜5行ぶんの高さを保ち、編集欄だけを縦にスクロールする。下の「削除」「登録／更新」はいつも見える。
- 一覧から選ぶと、`/settings/load_world_settings` で読み込んで編集欄に入れる。
- 「登場人物」「シナリオの目標」「シナリオパラメータ」は、YAMLをそのまま書く欄。初めて開いたときは、テンプレート（`/settings/get_template_world_*_yaml`）を初期値として入れる。
- 保存すると `/settings/save_world_setting` を呼び、一覧（`world_list`）に足す。
- 「削除」は、確認のダイアログを出してから `/settings/delete_setting` で世界設定のファイルを消し、一覧を取り直す。
  その世界のセッションは残る。まだ保存していない新規は、一覧から外すだけ。
- 世界カードで選んだ世界（編集する世界）は `edit_world_id` に持ち、メイン画面で遊ぶ世界（`selected_world_id`）とは別にする。
  世界カードで選ぶ・保存するだけでは、メイン画面の世界は変わらない。
- 遊んでいる世界を保存・削除したときは、メイン画面に知らせる（上の「画面どうしの連絡」）。削除したときは、メイン画面の選択が外れる。

## 接続環境設定（`settings.html`）

<div align="right"><a href="#top">▲ 目次へ</a></div>

| 項目・ボタン | 動き |
|---|---|
| FlaskサーバーURL | サーバーの接続先。単体なら `http://127.0.0.1:5000`、別のPCで動かすならそのPCのアドレス |
| ベースチャットパス | このフォルダの場所 |
| ベースパス | LocalFlaskServer の場所 |
| 「エクスプローラー」 | サーバー側のPCでフォルダ選択を開く（`/settings/select_base_path`） |
| 「サーバー起動確認」 | `/health` |
| 「SystemSettingsYamlを編集」 | サーバー側のPCで設定YAMLを開く（`/settings/open_system_yaml`） |
| 「モデルロード」 | `/settings/load_model`。`system_settings.yaml` のモデルを、モデルサーバーを再起動せずに読み直す。終わるまでボタンを止め、結果（読み込んだモデルの名前、または失敗の理由）を出す |

- 「適用」を押すまで、入力は保存されない。

## タグ

<div align="right"><a href="#top">▲ 目次へ</a></div>

- **タグ管理のウィンドウ**: メイン画面の上部の「タグ」で開き、もう一度押すか右上の「×」で閉じる。
  - タグの一覧は、Web側フォルダの `tags/tags.yaml`（「タグ一覧: [名前, ...]」）にあり、開くたびに `/settings/load_tags` で読む。
  - **登録**: 入力欄にタグ名を書いて「登録」か Enter で、一覧の最後に足す。空の名前と、同じ名前の二重登録は断る（通知を出す）。30文字まで。
  - **編集**: 「編集」で、その行の名前が入力欄になる。「保存」か Enter で確定、「キャンセル」か Esc で戻す。ほかのタグと同じ名前には変えられない。
  - **削除**: 確認のダイアログを出してから、一覧から消す（ファイルからも消える）。
  - 登録・編集・削除は、一覧を直してから `/settings/save_tags` で丸ごと保存する。保存に失敗したら、画面の一覧を保存前に戻す。
  - **フィルター**: 入力した文字を含むタグだけを出す（保存はしない）。当てはまるものが無ければ、その旨を出す。
  - 各行の左の丸には、タグ名の1文字目を出す。
- **キャラクター・プレイヤーに付けるタグ**（キャラクターカード・プレイヤー設定の「タグ」の行）
  - 「**設定**」で、タグを選ぶウィンドウを重ねて開く。タグ管理の一覧（`tags/tags.yaml`）をチェックボックスで並べ、付けているタグにはチェックを入れておく。
    複数選べる。「OK」で編集欄のタグにし、「キャンセル」か「×」で何もしない。
  - 付けているタグは、行に並べ、タグごとの「×」で外せる（編集はできない）。「**全削除**」で全部外す。
  - 選ぶ・外す・全削除は、編集欄の中だけの変更。「**登録／更新**」で、名前や設定の本文と一緒に保存する（設定YAMLの「タグ」。本文の欄には出さない）。
  - タグ管理から消したタグが付いていれば、付いたまま残す（タグを選ぶウィンドウには出ないが、OK を押しても外れない。外すなら「×」）。
  - 新規チャットでセッションへ写すときは、タグを外す（チャットや記憶のプロンプトに入れない）。
- **【要確認 Q51】** タグで何をするか（一覧の絞り込み、プロンプトへの反映、など）。タグ管理と、キャラクター・プレイヤーへの付け方は作った（2026-10-24）。使い道が決まっていない。
